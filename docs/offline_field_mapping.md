# 收到现场数据后，在开发机上建图和检查闭环

一个路线文件夹对应一次分析。命令会启动本机 FAST-LIO2，播放包里的原始点云和内置 IMU，逐帧保存估计轨迹、累积已经配准的点云，并生成三维预览和首尾对比图。PC3 和 H2 都可以离线。现场交付步骤见[现场采集教程](field_pointcloud_capture.md)。

## 1. 在开发机准备输入

在开发机的 `H2_project` 项目根目录打开终端。如果是首次安装的工作区，请先完成 Jazzy 安装、映射依赖和项目包构建。[安装与构建步骤](first_hardware_test_tutorial.md)

```bash
source /opt/ros/jazzy/setup.bash
source install/mapping/local_setup.bash
source install/ros/local_setup.bash
ls data/from-h2/site-001/
```

最后一行会列出各段名称，例如 `loop-日期-时间` 或 `area-A01-日期-时间`。读入本次要看的那一段，然后按现场交付的 SHA-256 清单核对。早期静止会话没有这份清单，可以直接用其会话目录执行第 2 步。

```bash
read -r -p '粘贴本次路线的目录名：' route_name
route="$PWD/data/from-h2/site-001/$route_name"
(cd "$route" && sha256sum -c SHA256SUMS)
cat "$route/route.txt"
```

校验失败时先补传文件，再做分析。查看操作员记录，尤其是是否确实回到了同一标记、同一朝向，以及首尾两次静止期间是否转过头。

## 2. 运行一次离线建图

已经确认走回原标记且朝向一致时，运行下面这一条。

```bash
python3 tools/offline_map.py "$route" --route-kind loop
```

开放路线改为 `--route-kind open`，全程静止改为 `--route-kind stationary`，起终点情况不清楚时省略这个选项。该参数控制报告中首末差值的解读，四种情况使用同样的估计和拼接算法。入口也接受旧会话目录（其中含 `bag/`）以及直接含 `metadata.yaml` 的 bag 目录。

默认半速回放。两分钟数据约需四分钟播放，另加初始化、队列处理和导出时间。等终端打印“完成”。结果位于项目的 `data/analysis/路线名-分析时间/`，终端会给出准确的绝对路径。重复分析会建新目录。每次只运行一个本机离线回放，以便域 167 中的输入和输出都对应本次数据。

## 3. 先看这三样

| 打开哪个文件 | 怎么看 |
| --- | --- |
| **`viewer.html`** | 在浏览器打开即可旋转、缩放三维点云和轨迹。先找现场记录里的门框、墙角和走廊转折，再观察同一堵墙有没有被拼成两层。预览使用抽样点，完整的体素点云保存在 `map.ply`。 |
| **`trajectory.png` 和 `pointcloud.png`** | 比较 XY 和 XZ 两个投影。看轨迹是否确实离开起点、转过预期的弯，以及墙面是否随经过次数增加而分叉。坐标单位为米，起点与终点各有标记。 |
| **`summary.md` 和 `closure_overlay.png`** | 查看首末位置和角度差，再对照前后各 3 秒的点云。叠加图用两种颜色标出首、末窗口，同一投影像素中的两路点另用一色。优先找两次都看见的固定物体。 |

**怎样读闭环数字。** “首末单帧”直接比较第一个与最后一个估计位姿。“首尾窗口”取两端各 3 秒的代表位姿，减小单帧抖动。先看窗口内的位置波动，确认与现场静止描述相符。若真实终点没有回到起点，报告中的数值同时包含真实位移。累计路长包含估计抖动，静止时也可能大于零。分析窗口太短时，仅报告可计算的指标。

**怎样读点云重合。** 程序将起点窗口和终点窗口直接放在同一个三维网格，分别计算两端被对方覆盖的体素比例。比较网格默认 0.30 m，若输出地图体素更粗则随之加粗。头部朝向、遮挡和视野差异都可能影响重合比例。图中的重合色对应二维投影，结合两个方向和三维图判断。项目当前输出 FAST-LIO 的原始估计，未对首尾强行对齐。动态场地的可接受偏差要结合实际任务和参考测量确定。

**怎样读数据连续性。** 摘要列出实际回放消息头的平均频率、最大相邻间隔和大于 2.5 个名义周期的间隔数。参考频率为点云 10 Hz、IMU 200 Hz。碰到突出的间隔时，结合两端的现场遮挡、停顿和轨迹图检查。各流时间戳的连续性不能单独验证两流的硬件同步。

## 4. 导出与排查

- `trajectory.csv` 包含整数纳秒时间戳、自首帧起的秒数、XYZ 米制位置和 XYZW 四元数。父坐标系为 FAST-LIO 的 `camera_init`，子坐标系 `body` 对应雷达组件估计。雷达装在 H2 头顶，头颈运动会改变传感器轨迹与机身轨迹的关系，XY 投影也受初始传感器姿态影响。
- `map.ply` 可以用支持 PLY 的三维点云软件打开。每个非空体素保留一个点，坐标是落在该体素内的全部有效世界系点的平均值。默认边长 0.10 m。若大场景触发体素数量上限，可用 `--voxel-size 0.20` 在新目录重跑。原始 bag 保留全部采样。
- `report.json` 保存完成状态、现场采集报告状态（如有）、运行参数、回放计数、首尾窗口和重合指标。`replay-diagnostics.json`、`parameters.yaml`、`fastlio.log`、`player.log` 供排查。源码和输出中的厂家标称外参描述的是 MID-360S 内部激光与 IMU 的关系。
- 失败时先看终端报错和 `report.json` 的 `failure`。缺少两个话题、缺少数据库分片、输入计数不符、源时间戳倒退、输出点云与位姿无法按时间戳配对，都会导致失败。回放还检查首尾覆盖和大于 1 秒的里程计空档。如果机器在播放时处理不过来，可关闭其他回放后用 `--rate 0.25` 重试，对比原包的消息数和时间。失败目录保留诊断，重跑时使用新目录。

第一次两分钟闭环建议把 `summary.md`、三张 PNG 和操作员的路线说明放在一起审阅，再反馈是否扩大采集。本工具处理单个连续 bag，多段地图合并和 RTAB-Map 全局闭环优化是后续工作。
