# H2 自主定位导航首版功能范围基线 V1.0

冻结日期：2026-11-02。状态：按用户“先固定首版功能范围”的指令建立首版范围基线；功能尚未实现或完成实机验收。

本文规定首版必须交付的能力、运行边界和失败行为。总体架构见 [software_architecture.md](software_architecture.md)。具体依赖提交、消息定义、参数值和验收测量细节在实现阶段收敛；不得用“待实测”隐去必需功能或停止机制。

## 1. 固定目标与使用边界

首版目标：H2 在已建图、已验收的室内平层区域完成“建图 → 自动初定位 → 单点/多点导航 → 障碍处理 → 失锁停车和重定位 → 任务反馈”的闭环。

| 项目 | 首版固定范围 |
| --- | --- |
| 机器人与执行边界 | 宇树 H2；PC3 输出高层速度，原厂控制器负责步态、平衡与关节控制 |
| 传感器 | 一台 MID-360 及其内置 IMU 为定位主传感器；H2 状态、关节和机身 IMU 用于机体变换、监测及一致性检查 |
| 实机平台 | PC3 NVIDIA Thor，Ubuntu 24.04 / ARM64，ROS 2 Jazzy |
| 开发平台 | 当前 Ubuntu 24.04 / x86_64；同一套源码分别构建，不将 x86 可执行文件当作 ARM64 部署产物 |
| 使用场景 | 已验收的室内平层走廊、房间及净宽满足要求的门口；一次激活一张地图 |
| 机器人姿态 | 雷达刚性固定于背包/躯干；运动采用已验证的手臂/腰部工作姿态与保守全身包络 |
| 运动能力 | 低速前进、已验证的转向；首版不启用侧移、倒退和自动旋转脱困 |
| 操作入口 | RViz、命令行和 ROS 2 接口；保留原厂遥控接管 |

最低依赖边界保持：FAST-LIO2 类 LIO 前端、RTAB-Map 建图/定位后端、Scan Context 候选检索及几何验证、Nav2 导航、高层 SDK 适配与独立运行监护。算法实现及版本选择可在保持接口和功能承诺的前提下调整。

## 2. 必须交付的功能

| 编号 | 功能 | 首版必须达到的行为 |
| --- | --- | --- |
| F01 | 传感器与机器人接入 | 接收 MID-360 点云/IMU 和可用 H2 状态，检查时间、频率、新鲜度及必要字段；连接异常可诊断 |
| F02 | 激光惯性里程计 | 支持初始化、身体回波过滤、逐点去畸变、连续 6DoF 里程计及质量反馈；提供 Nav2 所需平面状态与唯一局部 TF |
| F03 | 人工建图 | 人工遥控采集，完成关键帧、有效闭环和图优化；支持保存与重新加载，支持审核地图后用于导航 |
| F04 | 地图包管理 | 保存 RTAB-Map 数据库、三维地图/子图、二维通行地图、地点索引、禁行/限速区域、航点及标定/版本元数据；加载时检查一致性 |
| F05 | 地图定位跟踪 | 在冻结地图中跟踪并报告有效、退化、失锁等状态；通过审核的全局校正只作用于 `map→odom` |
| F06 | 自动初定位与重定位 | 缺少可信初值时检索多个地点并做几何验证；失锁后先停车，再在稳定观测下自动尝试；支持拒绝和人工初值兜底 |
| F07 | 单目标导航 | 接收地图坐标下的位置/朝向目标，规划、跟踪并返回到达、失败或取消结果；不可执行的目标明确拒绝 |
| F08 | 多航点导航 | 顺序执行航点，反馈当前索引和结果；中途失败不自动跳过，不无限重试，不继续执行后续点 |
| F09 | 障碍与门口处理 | 使用三维观测形成通行代价和碰撞限制；对观测范围内障碍减速/停车，等待或在可验证空间内绕行；门口按全身包络和误差余量准入 |
| F10 | 任务控制 | 支持开始、暂停、恢复、取消及状态查询；取消清除活动目标及剩余航点，旧任务不因重启或再次就绪复活 |
| F11 | 指令与运行监护 | 实现单一 SDK 运动写入点、控制权仲裁、速度限制、指令有效期、运动许可、模块故障及通信失效处理 |
| F12 | 诊断、回放与部署 | 提供状态/故障原因、关键数据记录、rosbag 回放、启动配置、构建部署说明；模拟与回放模式禁止写入实机运动接口 |

地图更新是人工操作：首版允许人工设置禁行/限速区域和航点，并重新发布地图版本；不要求专用地图编辑器。载入或更换活动地图前停止任务，重新定位后才能开始导航。

## 3. 定位、障碍与任务恢复语义

### 3.1 自动定位的成功与失败

- 自动初定位/重定位仅在地图有覆盖、雷达/IMU 正常、外参与时间链有效、机体稳定且观测足够时执行。
- 检索和几何配准必须允许返回“无可靠结果”。描述子分数、单次低残差或持续广播的 TF 均不能独立证明定位成功。
- 地图外、低重叠、遮挡严重、几何退化、多个地点难以区分或超过尝试时间/次数上限时，保持停车并报告原因；不盲目移动或自转寻找特征。
- 人工初值同样需要地图匹配验证；输入初值不直接授予运动许可。
- LIO 自身失效或重启时先重新初始化，不能用不可靠局部位姿累计点云或伪造连续坐标；完成定位后按恢复条件处理任务。

### 3.2 明确区分恢复事件

| 事件 | 首版规定行为 |
| --- | --- |
| 普通临时障碍 | 在任务仍有效、未被人工暂停、感知/定位/控制状态持续有效时，障碍解除或找到安全绕行路线后自动继续 |
| 持续阻塞或无可行路径 | 等待/重规划受时间或次数约束；达到上限后任务失败并停车，多航点任务不跳过受阻点 |
| 仅全局定位失锁，局部 LIO 与 H2 状态仍有效 | 停车并自动重定位；只有稳定匹配验证通过、控制权未变化、原任务仍有效且未人工暂停/取消时，重新规划后才可自动续行 |
| 自动重定位失败或歧义 | 保持停车和任务暂停，报告原因并接受人工初值/后续明确指令；不反复无限尝试 |
| 人工暂停 | 保留剩余任务，持续禁止自主运动；显式恢复且就绪条件满足后重新规划 |
| 任务取消、原厂遥控接管 | 取消当前任务并清除剩余航点；重新获得控制权后需提交新任务，不恢复旧速度 |
| 急停、机体/通信故障、LIO 重启或进程重启 | 撤销运动许可；完成对应恢复和就绪检查后，需显式操作才能重新运行任务 |

自动恢复能力是首版交付内容，须独立验证。初次实机接入可以通过调试配置禁用自动续行；验收前必须验证启用后的全部前置条件和人工操作优先级。

### 3.3 运动与地图边界

建图与自主导航互斥：建图允许原厂遥控或经过项目指令链的人工速度控制，不要求已有全局地图；自主导航使用审核后的冻结地图，不边走边扩图。通过 PC3 发出的人工速度同样经过仲裁、平滑、碰撞限制和适配层。原厂遥控接管由原厂通道直接执行，并撤销自主控制。

首版的已验证转向包括正常路径对齐和目标调向；其扫掠空间也必须通过全身包络检查。自动旋转脱困、倒退和侧移保持禁用。窄门或转弯空间不满足保守包络时允许拒绝路线，不通过扭腰、收臂或侧身缩小碰撞轮廓。

雷达未观测到的区域不自动视为空地；楼梯口、坑洞风险区和未经验证的地面设置禁行边界。首版不保证单个高位雷达识别所有透明物、负障碍和近脚低矮障碍，运行区域必须按实际可见范围验收。

## 4. 明确不纳入首版

- 室外、坡地、楼梯上下、台阶/沟坎跨越、跨楼层与电梯导航。
- 自主探索建图、导航中在线扩图、自动改变正式地图及多机器人地图融合。
- 开门、搬运、操作物体、自动充电/回充、自动起身和足步/全身运动规划。
- 侧身穿窄门、侧移、倒退、自动自转脱困及依赖复杂身体姿态的通行。
- 人群轨迹预测、社会化导航、拥挤人群穿行与高速动态避障。
- 相机视觉融合、语义/VLM 导航、语音任务理解及双 IMU 紧耦合融合。
- 任意六自由度初始姿态、任意遮挡和地图外场景下必然成功的全局定位。
- 专用 Web/移动端操作平台、多机器人调度、远程云服务与无人值守生产运行。

## 5. 交付物与完成条件

| 交付物 | 完成条件 |
| --- | --- |
| ROS 2 源码工作区与依赖清单 | 可按文档重复构建，记录实际采用的依赖版本；x86 开发与 ARM64 实机分别验证 |
| 接口、参数及状态机说明 | 与实际源码/配置一致；单位、坐标、时间语义、有效期和错误反馈可核查 |
| 启动与部署工具 | 至少包含只读接入、回放、人工建图和地图导航入口；回放/模拟无实机运动写入，实机重启不自动开始任务 |
| 地图包与配置模板 | 地图、地点索引、航点和标定版本一致；缺失关键实机配置时明确拒绝启用运动 |
| 实测记录 | 在实机验收场地逐项记录 F01～F12 的成功、拒绝和故障行为；关键停止及接管项未通过不放行行走试验 |
| 运行文档 | 说明构建、配置、建图、导航、取消/接管、日志导出、常见故障及版本回退 |

本机编译、模拟输入及回放通过是开发证据；H2 上的 ARM64 构建、真实通信、步行定位、停止与接管测试是实机交付证据。仅完成源码或仅能展示 RViz 不视为首版功能完成。

## 6. 参数与实机验收待定项

功能范围按本文固定；下列数值不能在缺少实机证据时写成交付保证。

| 待确定项 | 确定方式及约束 |
| --- | --- |
| 固件、SDK、JetPack、网卡及状态字段 | 实机清点和构建/通信验证；不改变高层执行边界 |
| 雷达外参与腰部动态链、IMU/关节时间映射 | 安装测量、标定和数据检查；数据不可靠时限制姿态或调整安装 |
| 全身包络、门口净宽及误差余量 | 测量实际工作姿态和步行摆动，在指定路线验证 |
| 速度、转向、加减速度、指令超时与停车距离 | 从低速档实测；0.2 m/s 为初始调试起点，不是已验收上限 |
| 定位/到达误差 | 初步目标为位置 P95 ≤ 0.15 m、航向 P95 ≤ 5°、到达位置误差 ≤ 0.20 m；沿用架构中的候选目标，需确定真值方法和场景后冻结 |
| 重定位召回、错误接受、拒绝及耗时 | 采用独立核验的查询数据，包含地图外、反向启动、重复房间、遮挡和失锁恢复；记录样本量和适用区域 |
| 恢复与重试上限、监护阈值、端到端延迟 | 用故障注入和实机响应确定；上限必须有限，参数缺失不能绕过运动许可 |

验收路线、地图覆盖范围及数值指标必须在宣告首版交付前落实为测试记录。未满足某项验收条件时如实标记未完成，不能通过扩大拒绝范围使规定功能名义通过。

## 7. 范围维护

本基线是首版功能与失败行为的依据；总体架构及后续详细设计与本文冲突时，应同步修正。代码实现过程中补接口、修缺陷、做标定和调整参数属于当前范围；新增能力或删除本文规定功能时，按用户后续明确要求更新范围版本并列出差异。

固定范围不代表所有软件版本与参数已经冻结，也不代表实机验收已经通过。
